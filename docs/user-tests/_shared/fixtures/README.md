# UT-BSH-* shared fixtures

Bundles + catalog seeds + restore scripts consumed by the `UT-BSH-*` runtime
probes in [`worktree-branch-switcher-and-history.md`](../../worktree-branch-switcher-and-history.md).
Every artifact in this tree is generated by a script under `setup/`; do not
edit bundle binaries by hand.

## Layout

```
_shared/fixtures/
├── README.md                                 (this file)
├── repo-multi-branch.bundle                  multi-branch fixture (~22 KB)
├── repo-empty.bundle                         empty-repo fixture (~0.3 KB)
├── repo-detached.bundle                      detached-HEAD fixture (~22 KB)
├── catalog/
│   ├── branch-switcher.json                  catalog seed -> repo-multi-branch
│   ├── branch-switcher-empty.json            catalog seed -> repo-empty
│   └── branch-switcher-detached.json         catalog seed -> repo-detached
└── setup/
    ├── build-repo-multi-branch.sh            regenerates repo-multi-branch.bundle
    ├── build-repo-empty.sh                   regenerates repo-empty.bundle
    ├── build-repo-detached.sh                regenerates repo-detached.bundle
    ├── restore-repo-multi-branch.sh          test-runner contract (see below)
    ├── restore-repo-empty.sh                 test-runner contract
    └── restore-repo-detached.sh              test-runner contract
```

All three `.bundle` files are kept under the 200 KB ceiling agreed in the
[design doc](../../../design-docs/worktree-branch-switcher-and-history.md);
the largest two are ~22 KB.

## Bundle contents

### `repo-multi-branch.bundle`

- Local branches: `main`, `feat/header-redesign`, `bugfix/menu`.
- Remote `origin`: `origin/main`, `origin/feat/new-shell`, and a symbolic
  `origin/HEAD → origin/main`. The bundled `origin/*` refs were populated
  from a throwaway file-backed bare repo during build time; the URL is not
  preserved in the bundle (only the refs are), so consumers see remote
  refs without a reachable remote.
- `main` has exactly **60 commits**, so the History tab's first page (50)
  fills and a second page is available for `UT-BSH-DV-004` (infinite
  scroll).
- HEAD checks out on `feat/header-redesign`.
- `README.md` is committed with content `main version` on `main` and
  `feat/header-redesign version` on `feat/header-redesign`, so editing
  `README.md` on the worktree creates a switch-blocking conflict
  (`UT-BSH-BP-008` dirty-tree case).

### `repo-empty.bundle`

- `git init`'d, **zero commits, zero branches, zero remotes** after the
  restore script runs.
- The bundle ships a single throwaway commit on a `__fixture_seed__` branch
  because `git bundle create --all` refuses to bundle a fully empty
  repository. The restore script deletes the branch + gc's the seed object
  so consumers observe the canonical "unborn HEAD on refs/heads/main"
  state.

### `repo-detached.bundle`

- Same object graph as `repo-multi-branch.bundle`.
- HEAD detached at the third commit of `main` (oldest-first). The
  restore script recomputes the detach target from `git log --reverse main`,
  so the chosen SHA is invariant across regenerations.

## Catalog seeds

`catalog/branch-switcher*.json` files conform to
`CodansCore.Catalog`'s `Codable` shape (`catalog.json` schema v3). One
`"playground"` project, one worktree, both pointing at the placeholder
`__TMP__/repo-multi-branch` (or `repo-empty` / `repo-detached`). The
**`__TMP__` placeholder is replaced by the test runner with the actual
per-run tmpdir** before the file is written to
`~/.config/codans/catalog.json` and the app is launched.

Fixed UUIDs are used for project + worktree IDs so generated configs
are diff-stable and the test runner can reference identifiers without
post-launch discovery.

## Deterministic-SHA invariant

The build scripts pin `GIT_AUTHOR_*` / `GIT_COMMITTER_*` env vars to
`Test <test@example.com>` at a fixed timestamp (`2026-01-01T00:00:00Z`
plus a monotonic per-commit offset). `git repack -a -d` + `git gc
--prune=now` are run before bundling so the resulting packfile's object
order is invariant. On the same `git` version, regenerating any bundle
produces a byte-identical file — verify with:

```bash
shasum docs/user-tests/_shared/fixtures/repo-multi-branch.bundle
bash docs/user-tests/_shared/fixtures/setup/build-repo-multi-branch.sh
shasum docs/user-tests/_shared/fixtures/repo-multi-branch.bundle   # same hash
```

Cross-version determinism is **not** guaranteed — major `git` upgrades
may change packfile heuristics. If the byte hash drifts, the bundle's
*git content* (`git bundle list-heads`) must still be invariant; reviewers
should compare the head list rather than the file hash when validating a
regenerated bundle on a different git release.

## Restore contract (test runner)

For every UT-BSH-* case the runner runs, before launching the app:

```bash
bash docs/user-tests/_shared/fixtures/setup/restore-repo-multi-branch.sh "$TMPDIR/repo-multi-branch"
# (or restore-repo-empty.sh / restore-repo-detached.sh per case)
```

Then:

1. Read `catalog/branch-switcher.json`, replace every `__TMP__` with the
   absolute path of `$TMPDIR`, and write the result to
   `~/.config/codans/catalog.json` (atomically, mode 0600).
2. Launch the app.

On teardown:

1. Quit the app.
2. `rm -rf "$TMPDIR"`.

The restore scripts always start with `rm -rf <dest>` so a stale dest
directory is replaced rather than appended-to. They also set
`user.name` / `user.email` so any in-test git commit performed by an
assertion does not fail with "please tell me who you are".

## Regenerating from scratch

```bash
# all three bundles, in order:
bash docs/user-tests/_shared/fixtures/setup/build-repo-multi-branch.sh
bash docs/user-tests/_shared/fixtures/setup/build-repo-empty.sh
bash docs/user-tests/_shared/fixtures/setup/build-repo-detached.sh

# verify nothing else changed:
git status docs/user-tests/_shared/fixtures/
git diff --stat docs/user-tests/_shared/fixtures/
```

The build scripts each accept an optional output-directory argument; the
default is the fixtures root directory (`_shared/fixtures/`). Pass a
custom directory when scratch-building for inspection without overwriting
the checked-in bundles.
